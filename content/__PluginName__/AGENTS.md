# AGENTS.md — __PluginName__

Instructions for coding agents working in this project. It was generated by the
`nodeaec-revit-plugin` template: an Autodesk Revit add-in (Revit 2023–2027) whose paid
commands are licensed through Node.aec.

Before any task that touches licensing, the Ribbon, the build or packaging, load the skill
[`.agents/skills/licensing-integrate/SKILL.md`](.agents/skills/licensing-integrate/SKILL.md).
It holds the detailed steps and rules; this file is the project map and the rules that
must never break.

## The rule that outranks everything: licensing is fail-closed

- Every paid command calls `Gate.Validate(ProductSlug)` as its **first statement** and runs
  its feature only when `gate.IsLicensed` is `true`.
- Not licensed: show `gate.GetMessage(language)` as-is with the `Open Node.aec Connector...`
  link, then `return Result.Cancelled;` (copy the pattern in `Commands/HelloCommand.cs`).
- Never wrap the gate in a `try/catch` that lets the command run, never branch on
  `gate.Reason` or the message text, and never show or log `gate.LicenseKey`.

## Common tasks

- **Add a paid command:** a new `IExternalCommand` in `Commands/` whose first lines are the
  gate from `HelloCommand.cs`, plus a button in `App.cs` (`AddButtonIfMissing`, a unique
  internal name). With several commands, move `ProductSlug` to one shared static class.
- **Build:** `dotnet build -p:RevitYear=2023`, `2025` and `2027` (one per compatibility
  group); each must end with 0 errors.
- **Release:** `powershell -ExecutionPolicy Bypass -File scripts/release.ps1 -Version <x.y.z>`;
  `-Version` must equal `<Version>` in the csproj. `-Install` also installs the bundle on
  this machine (Revit must be closed).
- **Validate:** the manual Revit checks in
  `.agents/skills/licensing-integrate/references/validation.md`. They need a real Revit
  session; report the ones the user still has to run instead of claiming them.

## Never

- Create a Ribbon tab of your own; panels go in the `Node.aec` tab.
- Ship `RevitAPI*.dll`, `AdWindows.dll`, `UIFramework*` or `NodeAec.Connector.dll`, or
  reference the Connector in any way.
- Add HTTP calls, login screens or license-key handling: the Node.aec Connector does that.
- Change `AppId`, `ProductCode` or `UpgradeCode` in `scripts/` after the first release, or
  make them differ between `release.ps1` and `installer.iss`.

## Facts that go stale, and where to check them

Do not trust a version written in a doc or a comment; check its source:

| Fact | Source of truth |
|---|---|
| This plugin's version | `<Version>` in `__PluginName__.csproj` |
| Lite version to build against | Latest: <https://www.nuget.org/packages/NodeAec.Licensing.Lite>. Use the version the current Node.aec Connector ships, or older: the `PackageReference` in [revit-connector `src/NodeAec.Connector/NodeAec.Connector.csproj`](https://github.com/nodeaec/revit-connector/blob/main/src/NodeAec.Connector/NodeAec.Connector.csproj) |
| `Snapshot` members, `GateReason` values and messages | [licensing-lite README](https://github.com/nodeaec/licensing-lite#readme) |
| Revit year → target framework, Revit API package versions | `TargetFramework` / `RevitApiPkgVersion` in `__PluginName__.csproj`; compare with the [Sample Plugin's csproj](https://github.com/nodeaec/revit-sample-plugin/blob/main/src/SamplePlugin/SamplePlugin.csproj) when adding a Revit year |
| The licensing skill | Canonical copy: [revit-sample-plugin `.agents/skills/licensing-integrate/`](https://github.com/nodeaec/revit-sample-plugin/tree/main/.agents/skills/licensing-integrate). Replace the local folder with it when they differ. |
| Newer template output | <https://www.nuget.org/packages/NodeAec.Templates.RevitPlugin>; scaffold a throwaway project with the new version and compare it with this one |

After changing a version, find every place that repeats it:
`grep -rn "<old value>" .` (excluding `bin/` and `obj/`).
